# Messaging rules for Engage assets

The rules every Engage asset follows when it uses this design system: decks, playbooks, pages, product copy, social posts.

The approved wording itself (category, headlines, claims, proof points) is managed in Engage's internal messaging framework, which is the source of truth. It is deliberately not published here. Use the framework for what to say, and this file for how to say it.

## Language

- **UK English** throughout: personalise, colour, organisation, behaviour, programme.
- **No em dashes.** Use a full stop, a comma, a colon or brackets instead. This applies to all copy, including headings, captions and alt text.
- Sentence case for headings, buttons and navigation. Uppercase is only for the small letter-spaced eyebrow label.
- No emoji in interface or document copy.

## Words and phrases to avoid

| Avoid | Why |
| --- | --- |
| Community Engagement Platform, CEP | Retired category name |
| experience management, EX platform, survey platform | Wrong category |
| CDP, operating system | Wrong category |
| unlock, revolutionise, seamless, next-gen, empower | Generic AI-sounding filler |
| competitor names | Never name competitors in Engage copy |
| numbers, logos or customer outcomes with no approved source | Every claim needs a source |

Never put customer names, personal data or real people's photos in templates, examples or sample screens. Use clearly fictional placeholders.

## Appi

Appi is introduced after the opening statement, not in it. Do not name Appi in a hero headline, a hero subheading or the eyebrow above them.

## How to write a line

- **One job per line.** A headline, a subheading, a category label and a call to action each do one thing. Do not stack them into a single string.
- **Short, declarative sentences.** One idea per section.
- **Say it once.** If a later line repeats an earlier one, cut the later one.
- In website and campaign assets, pair the sans headline with one serif-italic emphasis word (see the signature device in `engage-appi-design-system/readme.md`). Document-mode headings (playbooks, guides, explainers, one-pagers) are plain sans, with no serif word (see `SKILL.md`).

## Before you publish

- [ ] UK English, no em dashes
- [ ] None of the avoided words above
- [ ] Every number and claim has an approved source
- [ ] No customer names, personal data or real photos
- [ ] Matches the current approved wording in the messaging framework
